ANALYSTER

AI-Powered Insurance Claims Intelligence Assistant — Complete Architecture & Operational Guide

An exhaustive, end-to-end technical reference explaining every architectural decision, data pipeline stage, ML model, multi-agent interaction, API endpoint, and UI workflow.

1. Executive Overview: What Problem Do We Solve?

The Core Challenge: Insurance companies process thousands of complex property, casualty, and auto claims daily. Manual inspection is slow and vulnerable to fatigue, while black-box AI automation risks unfair denials and regulatory penalties.

Our Solution: Analyster is an enterprise decision-support system built for Human-in-the-Loop workflows. It combines Hybrid Graph-RAG retrieval, a 4-Layer ML Ensemble with SHAP explainability, and a 5-Agent Collaborative Swarm with explicit Agent-to-Agent (A2A) handoffs. The AI never makes unilateral final decisions—it assists human adjusters with grounded evidence citations, anomaly flags, and SIU forensic action items.

Key Operational Axioms:
  • Zero Hallucinations: Every assertion, amount, and risk factor is strictly grounded with database IDs (fact_claims, dim_policies).
  • Complete Auditability: Deterministic state-machine handoffs with full timestamped JSON execution traces.
  • Dual-Channel Retrieval: Dense vector semantics (narratives) + 2-hop graph topology (customer-policy clusters).

2. The 7-Stage End-to-End Execution Flow

Every single claim query or evaluation flows through the following 7 stages in strict sequence:

1

Claims Data & Ingestion (COIL 2000 Benchmark)

Ingests 86 demographic/policy attributes from the Insurance Benchmark dataset. Synthesizes 1,500 rich realistic claim records with realistic incident narratives, loss amounts, and ground-truth fraud anomalies.

2

Data Processing & Relational Storage (SQLite)

Cleans, imputes, and normalizes data into claims_intelligence.db across dim_customers, dim_policies, and fact_claims with a unified SQL view v_claims_full_dossier.

3

Hybrid Knowledge Base (ChromaDB + NetworkX)

Builds 384-dimensional dense vector embeddings using all-MiniLM-L6-v2 in ChromaDB and constructs a 25,543-node / 22,184-edge knowledge graph in NetworkX.

4

Risk & Anomaly Detection Engine (4-Layer Ensemble)

Calculates a calibrated composite risk score (0–100) using XGBoost (50%), Random Forest (25%), Isolation Forest (15%), and Rule Engine (10%) with SHAP feature attribution.

5

Multi-Agent Intelligence Mesh (5 Collaborative Agents)

Orchestrates 5 specialized autonomous agents (Retrieval → Risk → Anomaly → Summarizer → Investigation Support) via explicit A2A messages.

6

Claims Insights & LLM Synthesis (Gemini + Grounding)

Synthesizes a 100% grounded executive brief, 4-step forensic investigation checklist, and targeted claimant interview questions with zero-hallucination fallback.

7

Human Reviewer & Decision Studio (Frontend UI)

Presents an interactive studio with KPIs, interactive Knowledge Graph visualizer, What-If counterfactual simulator, and printable SIU case dossier.

4. "Which Code Follows What Code" — Detailed Execution Lifecycle

A. Startup & Pre-Warming Lifecycle

1. python -m uvicorn backend.api.main:app --host 0.0.0.0 --port 8000
   └── main.py (lifespan event)
       ├── Load SQLite DB: data/processed/claims_intelligence.db
       ├── Load ChromaDB Vector Store: data/chroma_store (1,500 embeddings)
       ├── Load NetworkX Graph: data/graph_store/insurance_knowledge_graph.graphml
       ├── Initialize 4-Layer EnsembleScorer (XGBoost, RF, Isolation Forest, Rules)
       ├── Initialize 5-Agent Swarm (ClaimsIntelligenceOrchestrator)
       └── Verify Google Gemini API Key via backend.agents.llm_service

B. End-to-End Claim Swarm Analysis Request (e.g., POST /api/claims/{id}/analyze)

When an adjuster selects a claim (e.g. CLM-2024-00003) and clicks "Run 5-Agent Swarm Analysis":

1

API Ingress (backend/api/routes.py)

Route receives HTTP POST, validates claim_id, and calls orchestrator.process_claim(claim_id).

2

Data Loading (orchestrator._fetch_claim_data)

Queries SQLite view v_claims_full_dossier to retrieve complete claim record, customer demographics, policy line, loss amount, and notes.

3

Agent 1: Claims Retrieval Agent (backend/agents/retrieval_agent.py)

• Queries ChromaDB for top-3 dense narrative embeddings.
• Traverses NetworkX graph for 2-hop neighbor connections.
• Emits A2AMessage(from="RetrievalAgent", to="RiskAgent") containing precedent cases and policy history.

4

Agent 2: Claims Risk Analysis Agent (backend/agents/risk_agent.py)

• Feeds features to EnsembleScorer (XGBoost + RF + IF + Rules).
• Extracts top 5 driving SHAP factor attributions.
• Assigns calibrated risk score (0–100) and triage tier.
• Emits A2AMessage(from="RiskAgent", to="AnomalyAgent").

5

Agent 3: Anomaly Detection Agent (backend/agents/anomaly_agent.py)

• Performs multidimensional feature isolation (amount vs income, filing delay velocity).
• Identifies pattern anomalies and cluster deviations.
• Emits A2AMessage(from="AnomalyAgent", to="SummarizerAgent").

6

Agent 4: Claims Summarization Agent (backend/agents/summarizer_agent.py)

• Constructs strict grounded prompt containing all facts from Agents 1, 2, and 3.
• Calls Google Gemini LLM to synthesize a concise, factual executive brief.
• If API is offline, gracefully executes deterministic fallback.
• Emits A2AMessage(from="SummarizerAgent", to="InvestigationAgent").

7

Agent 5: Investigation Support Agent (backend/agents/investigation_agent.py)

• Consolidates all agent findings into a structured SIU case package.
• Formulates 4 concrete forensic action items (e.g., dispatch surveyor, check CCTV, verify title).
• Compiles targeted claimant interview probes.
• Compiles complete ClaimsIntelligenceDossier.

8

Frontend Rendering (frontend/js/app.js)

Renders the full dossier in Claim Studio: timeline of A2A handoffs, animated risk gauges, SHAP factor bar charts, precedent cards, executive summary, and SIU referral generator.
